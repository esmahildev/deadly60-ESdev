## 1. Architecture

**Single config home: `Nights.as` (existing class).** Add static, data-only config there instead of a new class. ASSUMPTION: FFDec can add a new class, but editing an existing one is the proven path, so use that to avoid the risk. Contents:

- `finalNight:int` — 30 (Classic) or 60 (Extended). Replaces every literal 30 night check.
- Wave rows 31-60: generated by a function from per-band templates (type pools, queue length, cap), not 30 hand-typed arrays. Rows 1-30 stay byte-for-byte as they are.
- `nightNameList` extended to 59 names (nights 2-60).
- `statScale(type, night)`: returns the HP/speed/damage multiplier. Identical to the current formulas for n <= 30, soft-capped beyond. (Stats are currently linear and uncapped: VERIFIED, e.g. Green HP = 150 + 5n.)
- Event table (night -> event id), weapon-upgrade table, repair costs, XP table, difficulty knobs. All in one place.

**Principle:** every change must leave nights 1-30 numerically identical in Classic mode. This is checked by a test (see 5).

## 4. Save compatibility

- Format today (VERIFIED): `|`-separated sections 0-5, no version field, positional parse, extra trailing sections ignored.
- Plan: **append** new sections (6 = mode/version, 7 = weapon upgrade levels, 8 = box/turret HP, 9 = XP extras). Never reorder or insert.
- Loader hardening: missing section -> safe default instead of an exception (current code throws on a missing section, `Level.as:1805-1811`).
- Old save (no section 6): treat as Extended, upgrade levels 0, full object HP.
- Back up the SharedObject (`.sol`) before every test run. ASSUMPTION: location is Flash Player's `#SharedObjects` folder; confirm in Stage 3.
- Quit-mid-transition: checkpoint is written only at dawn in the base; write the new string in one assignment, as now. Note: no explicit `flush()` exists (VERIFIED by agent grep), so persistence relies on `close()`; test it.

## 5. Test strategy (no tests exist today)

1. **Runner (Stage 3 spike):** needs a way to run a patched SWF: Flash Player standalone projector or Ruffle, with `GameController.exe=false` to bypass Zinc. ASSUMPTION; verify both. Fallback: patch the EXE's embedded SWF (unknown feasibility).
2. **Regression oracle for nights 1-30:** a script that diffs `Nights.addNights` output (wave arrays, caps, stats at each n) between original and patched code in Classic mode. Must be identical. Strongest "original preserved" check.
3. **Test-only debug hooks:** jump to night N, give scrap, fast-forward (the original `Controller` already runs `level.update()` 4x when `debug` is set, `Controller.as:428`). Hooks are removed/disabled for release.
4. **Manual matrix per milestone:** new game; night 29 -> 30 -> 31; save/load at 29/30/31/59/60; final night + ending + defeat + replay; old-save continue; Classic mode unchanged; many-enemy performance (cap 20-26 at night 60); repeated room changes (leak/cleanup check).

## 6. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| FFDec cannot round-trip these classes (e.g. `[Embed]` annotations, closures) | Whole route blocked | Stage 3 no-op round-trip proof is the gate, before any feature work. |
| `Level.as` is a 3,598-line god class edited via bytecode-level tools | Collateral breakage | Smallest edits, one feature at a time, rebuild+test per step, backup every step. |
| Cutscene 6 fires at night 30 | Game ends mid-campaign | Explicit guard in section 2; test at nights 25, 30, 35. |
| Stats uncapped past 30 | 31-60 curve explodes | `statScale` soft cap; tune from playtests. |
| New art impossible | Features 3.3/3.7/traps cut | Phase plan: art-free work first. |
| Statics never reset (`Tracker`, `cutscenesPlayed`, `American.meet*`) | "Restart keeps state" bugs | Test restart/replay; reset only what the tests show is stale. |
| Repair exploit loop | Trivializes defense | Day-only/limited repair; fix re-entry full-heal. |
